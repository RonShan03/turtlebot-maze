# Workstation preparation before travel

Prepared 2026-11-19. Capture personal footage first; simulation and code can move to another Linux Docker host.

1. From `assignments/assignment-3`, install the project into a Python environment (`python -m pip install -e ".[test,download]"`). Run `python -m task2_stella_vslam.camera --help`.
2. Print a flat chessboard, count its **inner** corners, and measure each square in metres. With the final camera resolution/focus fixed, run `python -m task2_stella_vslam.camera capture --output data/personal/calibration --width 640 --height 480`. Press **S** for 20–30 sharp views, including tilted boards at edges, different depths and both orientations. Press **Q** to finish. A 9×6 inner-corner board is the CLI default; change `--board` during calibration for your actual pattern.
3. Run `python -m task2_stella_vslam.camera calibrate --images data/personal/calibration --board 9 6 --square-m 0.025 --output data/personal/calibration.json`, replacing 0.025 with your **measured** square width. Review RMS and per-view errors; recapture if warnings remain.
4. Record at the same resolution/focus: `python -m task2_stella_vslam.camera capture --output data/personal/recording --width 640 --height 480 --fps 30 --record --seconds 150`. Start with a textured area, move slowly sideways before turning, include walls/furniture from several viewpoints, and revisit your starting view. Avoid pure rotation, blank walls, mirrors, moving people and abrupt exposure changes. Press **Q** to finish early.
5. Validate and generate a corrected video plus matching YAML: `python -m task2_stella_vslam.camera video --input data/personal/recording/indoor.avi --calibration data/personal/calibration.json --output-video data/personal/indoor-undistorted.avi --report data/personal/video-report.json`. The adjacent `.yaml` has the new intrinsics and zero distortion. Use that YAML only with that derived video.
6. Copy `data/personal/` to storage you control before leaving. Raw footage/calibration images are deliberately ignored by Git. Commit the small measured calibration/report if desired, taking care with private interior imagery. Test the backup by opening the copied video.
7. Save the tested container images with `docker save ds685-vslam:latest turtlebot_behavior:overlay turtlebot-maze-demo-slam:latest -o ds685-images.tar` to external/private storage if the remote host cannot build them. This can be several GB; keep it outside Git. Check free disk space first.
8. Follow [REMOTE_ACCESS.md](REMOTE_ACCESS.md), then test from the travel laptop using a phone hotspot **before leaving**. Confirm you can run `docker ps`, the smoke test, and retrieve its evidence. Merely seeing the machine in Tailscale does not prove Docker remains usable after lock/reboot.

Calibration, personal recording, personal reconstruction and publication remain user-dependent until actual inputs exist. No personal camera parameters or video link are supplied as placeholders for measurements.
